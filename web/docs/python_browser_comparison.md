# Python 与浏览器对照

## 同一样本结果

样本只在本机私有目录使用，以下以 `private-name-roi-A` 表示；文档不记录路径、原文件名、图片或哈希。

| 指标 | Python MVP | 浏览器 PoC |
|---|---|---|
| 输入尺寸 | 119 × 37 | 119 × 37 |
| 原始文本 | `天府` | `天府` |
| 识别置信度 | 0.99978 | 1.00（两位小数显示） |
| 框 | 单行 API 以整张 ROI `[0,0,119,37]` 作为调用范围，无检测框 | 检测框 `[32,10,60,27]` |
| 总耗时 | 1071.94 ms，含首次 RapidOCR 初始化 | 97.8 ms；恢复后复跑 90.8 ms |
| 首次引擎初始化 | 572.85 ms | 模型兼容性检查单独记录，OCR 计时不重复加载模型 |

## 差异解释

- **文字一致**：浏览器使用同一 PP-OCRv6 recognition 模型和从模型 metadata 提取的 18,708 字符表，CTC 解码得到与 Python 相同的直接结果。
- **置信度显示差异**：Python 保留 5 位小数；PoC 为便于阅读把均值四舍五入到两位，因此 0.99978 显示为 1.00。没有手工改写文字或置信度。
- **框不可直接等价**：Python 本次 `single_line=True` 不运行检测，只能记录调用 ROI；浏览器先运行检测模型并给出轴对齐概率图近似框。两者框语义不同。
- **耗时不可直接等价**：Python 数字包含首次引擎和三个模型初始化；浏览器 OCR 数字在模型预加载后测量。应把浏览器模型加载表与 OCR 计时分开看。
- **后处理差异**：浏览器没有复制 OpenCV `findContours/minAreaRect`、Shapely/pyclipper unclip 和旋转裁剪，只实现轴对齐连通域近似。这是当前最大质量风险，不是模型不兼容。

## 结论

以上章节记录的是通用文字 ROI 入口，不代表结构化页面入口。当前新增的主星 smoke、辅星和经验星曜结构化执行层已有独立的 Python/浏览器对照与人工验收记录；通用入口仍不声称完整多行 OCR 或现有 Python 业务后处理完全等价迁移。
